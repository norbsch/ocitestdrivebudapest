Kubernetes telepítőcsomag ellenőrzése, 2026. november 17.

Cél: meglévő Basic OKE v1.37.1, managed amd64 node-ok, Cloud Shell privát API-eléréssel; meglévő normál OCI Load Balancer NodePort-bekötéssel; egy Streamlit-pod és egy LiteLLM-pod; konfigurálható külső PostgreSQL 16.

A résztvevő által bemásolt Cloud Shell-kimenet alapján a privát API-elérés működik, három Ready/amd64/VM.Standard.E5.Flex node látható, és nincs meglévő IngressClass, Ingress vagy alkalmazás LoadBalancer Service. Ez nem a csomag telepítésének tesztje.

Elvégzett helyi ellenőrzések:
- 18 offline teszt sikeres: szigorú TLS/URL-kódolás, konfigurálható DB-nevek, átmeneti SET jog visszaállítása CREATE DATABASE hiba után, csak olvasó DB-ellenőrzés, TLS hiányának visszautasítása, NodePort/ClusterIP elválasztás, Cluster forgalompolitika, egy-egy példány, nem root podok, Secret-mount jogosultság, adminjelszó kizárólag az init Jobban, app/proxy credentialök szétválasztása, képletöltési Secret, díjmentes probe útvonalak, Jobok automatikus újrapróbálásának tiltása, namespace/context hatókör, meglévő Secret megőrzése, titkos helyi fájl 0600 jogosultsága, redaktált hiba, bizonytalan kulcslétrehozás blokkolása és meglévő appkulcs újrafelhasználása.
- Python források és a Bash telepítő szintaxisa ellenőrizve.
- A guide parancsblokkjai Bash-szintaktikailag ellenőrizve; helyi dokumentumhivatkozások érvényesek.
- A konfigurációparsert és a tényleges renderelőt mesterséges adatokkal futtattuk: 8 Kubernetes JSON manifest generálható. A buildhez még hiányzó KUBE_CONTEXT elfogadott, a cluster-műveletekhez kötelező.
- A Dockerfile-ok csak alkalmazás-/runtime-forrásokat másolnak; whitelist alapú .dockerignore kizárja a helyi credentialöket.
- A csomag nem függ a VM-es Applications könyvtártól, /home/ubuntu útvonaltól vagy a fejlesztő workbench könyvtárától.

Még élő környezetben ellenőrizendő:
- A két konténerkép teljes Podman-buildje és OCIR push/pullja. A helyi fejlesztői környezetben nincs Podman/Docker futtató; kép-buildet nem állítunk sikeresnek.
- Kubernetes API-szerveres dry-run, ütemezés, tényleges podindulás és a Prisma-kliens futása a saját képben.
- PostgreSQL bootstrap/verify-full kapcsolat és LiteLLM sémamigráció a cél DB-n. A DB-bootstrap SQL-ágakat offline helyettesített kapcsolattal ellenőriztük.
- OCI API-kulcs tényleges modelljogosultsága, modellhívás, pozitív költség és konkrét spend sor.
- A meglévő LB → worker NodePort → Streamlit útvonal, HTTP/WebSocket és böngészős munkamenet.
- Cloud Shell tárhely- és buildkapacitás az adott sessionben.

A csomag készítésekor nem történt cluster-/OCI-módosítás, képfeltöltés, adatbázis-művelet, fizetős modellhívás vagy Git-push. Az új csomagot a felhasználó másolja majd a repo KubernetesApplications könyvtárába. Nem tartalmaz tényleges jelszót, API-kulcsot, registry tokent vagy kubeconfigot.
