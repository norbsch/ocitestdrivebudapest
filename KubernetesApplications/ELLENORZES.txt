Kubernetes telepítőcsomag ellenőrzése, 2026. november 17.

Elvégzett élő műveletek:
- A felhasználó kifejezett kérésére létrejött az oci-ai-image-builder VM a gergo_peter_labs compartmentben, Frankfurtban: Ubuntu 24.04, AMD64, E5 Flex, 2 OCPU, 16 GB memória, 100 GB boot volume.
- Külön builder subnet és security list készült a meglévő litellm-demo-vcn-ben; az SSH a tényleges munkaállomás-kilépőcím /32 tartományára korlátozott. A meglévő app/DB/OKE erőforrásokat nem módosítottuk.
- Docker 29.1.3, Skopeo, Git, Python 3 és rendszerfüggőségek telepítve.
- Mindkét kép Linux/AMD64 buildje sikeres. A Docker által jelzett teljes méret: Streamlit 809 MB, LiteLLM 2,12 GB.
- Streamlit importpróba és ideiglenes localhost-konténer HTTP health teszt: 200 ok. A tesztkonténert eltávolítottuk.
- LiteLLM, Prisma, psycopg, cryptography és az OCI chat provider offline importpróbája sikeres. A Prisma-kliens build közben generálódott.
- Mindkét kép feltöltve a frgmw9rkvlkd namespace két jóváhagyott Public repositoryjába, workshop-v1 taggal. Az images.env a tényleges registry digesteket rögzíti.
- A feltöltéshez a munkaállomáson meglévő OCI API-hitelesítéssel, repositoryra korlátozott és egyórás registry access tokeneket kértünk. A token SSH stdin csatornán, átmeneti Docker-konfigurációba került; nem került argumentumba, képbe vagy Gitbe. A VM-re OCI API-privátkulcsot nem másoltunk.
- Anonim registry-manifest olvasás, digest- és platformellenőrzés, valamint mindkét kép teljes anonim Skopeo-letöltése sikeres.
- A korábbi Docker-alapú résztvevői `python3 tools/pull_images.py --sudo` parancs az Ubuntu build VM-en is sikeresen lefutott: üres Docker authkonfiguráció, mindkét digest és Linux/AMD64 platform ellenőrizve. A Docker ekkor már rendelkezett a rétegekkel; a teljes anonim rétegletöltést a külön Skopeo-próba igazolta. A VM-en 90 GB szabad hely maradt.

- A korábbi `python3 tools/pull_images.py` Skopeo-parancs Ubuntu 24.04-en sikeresen letöltötte mindkét teljes képet fájlokba; a digest és a Linux/AMD64 platform ellenőrzése is sikeres. Ez a segédeszköz az új Cloud Shell guide-nak nem része, a résztvevőnek nem kell futtatnia.

Helyi ellenőrzések:
- A résztvevői guide 10 lépésből áll, kizárólag Cloud Shellből történő telepítéshez. Az előre telepített OCI CLI és kubectl ellenőrzésével indul, a Cloud Shell beépített hitelesítését megtartja. A LiteLLM saját API-kulcsot kap.
- A fő útvonalban nincs helyi image-letöltés vagy konténerfuttatás. A képeket az OKE tölti le közvetlenül a nyilvános OCIR-ből. A hibakeresés, frissítés és eltávolítás az UZEMELTETES.hu.md fájlba került.
- 34 offline teszt: DB TLS/URL-kezelés, DB-bootstrap szerepkör-kezelés, manifestek, nem root podok, namespace/context, Secret-megőrzés, public registry tokenmentes résztvevői telepítése, kiadási képcímek átvétele, publikációs hibák utáni kiadásmegőrzés, authfájl törlése, platformellenőrzés, a munkaállomás-letöltő anonim hozzáférése és hibás digest/platform elutasítása.
- Python 3.9-kompatibilis szintaxis, a guide Bash parancsblokkjai, helyi hivatkozások, 8 Kubernetes manifest renderelése és a csomag ellenőrzőösszegei ellenőrizve. A script public képeknél nem kér registry-tokent, és a podok nem kapnak imagePullSecretet.
- A .dockerignore whitelist alapján csak az alkalmazás-/runtime-források kerülnek a build contextbe. A csomag nem tartalmaz valódi jelszót, privát kulcsot, registry tokent vagy kubeconfigot.

Még nem ellenőrzött élő telepítési lépések:
- A friss Cloud Shell guide teljes, elejétől végéig történő végrehajtása. A beépített eszközök, CLI-hitelesítés és feltöltés lépései hivatalos OCI dokumentáció alapján készültek.
- A résztvevő aktuális Cloud Shell sessionjének hálózati elérése az OKE API-hoz.
- Kubernetes API-szerveres dry-run, podütemezés és futás a résztvevő OKE clusterén.
- PostgreSQL bootstrap, verify-full kapcsolat és LiteLLM sémamigráció a cél adatbázison.
- GenAI modellhívás és a konkrét hívás költségének/spend sorának ellenőrzése.
- A meglévő Load Balancer → worker NodePort → Streamlit útvonal, HTTP/WebSocket és böngészős munkamenet.

A jelenlegi műveletekben nem történt clustertelepítés, DB-módosítás, fizetős modellhívás vagy Git-push. A Cloud Shell korábbi 4,6 GiB-os tárhelyén a LiteLLM kép végső commitja meghiúsult; a PUBLISH.hu.md ezért a külön build VM-et használja.
